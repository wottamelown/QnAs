# FortiSOAR Interview Preparation

## 1. FortiSOAR Overview

### What is FortiSOAR?

**FortiSOAR** stands for **Fortinet Security Orchestration, Automation, and Response**.

It is a SOAR platform used by Security Operations Centers to:
- Automate repetitive security tasks
- Coordinate incident response
- Integrate security tools
- Improve the speed and consistency of investigations

**Key Point:** FortiSOAR does not replace a SIEM, firewall, EDR, or analyst. Instead, it connects these systems and orchestrates actions between them.

### Simple Example

A typical workflow:
1. SIEM detects a suspicious IP address
2. SIEM sends an alert to FortiSOAR
3. FortiSOAR creates or updates an Alert record
4. A Playbook extracts the IP address
5. FortiSOAR uses Connectors to query threat-intelligence services
6. It enriches the indicator with reputation and geolocation
7. If malicious, it blocks the IP on FortiGate
8. It creates an incident and assigns tasks to the SOC analyst
9. It sends an email or Teams notification
10. It records the actions and results

### Core FortiSOAR Terminology

| Term | Meaning |
|------|---------|
| **Alert** | Notification generated by a security tool or detection source |
| **Incident** | Case representing a suspected or confirmed security event |
| **Indicator** | Potentially malicious observable (IP, URL, domain, hash, email) |
| **Playbook** | Automated workflow containing actions and decisions |
| **Connector** | Integration used to communicate with another product or service |
| **Action** | Specific operation performed by a connector |
| **Data Ingestion** | Process of importing alerts or data from external systems |
| **Enrichment** | Adding context to an indicator or alert |
| **Mitigation** | Actions taken to contain or reduce the threat |
| **War Room** | Collaborative workspace for handling a major incident |
| **Task** | Manual or automated action assigned during investigation |
| **Campaign** | Group of related incidents associated with a threat actor or activity |
| **Solution Pack** | Prebuilt package with modules, playbooks, connectors, dashboards |
| **Widget** | UI component used to display information or perform actions |
| **Content Hub** | Repository for solution packs, connectors, widgets, and other content |
| **Jinja** | Template language used to reference and manipulate data in playbooks |
| **Trigger** | Event or condition that starts a playbook |
| **Record** | Individual entry in a FortiSOAR module |
| **Module** | Data model or functional area containing records |

**Note:** The SOAR Framework Solution Pack provides foundational incident-response modules such as Alerts, Incidents, Indicators, dashboards, reports, and playbooks. In recent FortiSOAR releases, this framework is installed by default with fresh installations.

## 2. Top FortiSOAR Interview Questions and Answers

### Fundamentals

#### Q1. What problem does FortiSOAR solve?

**Answer:** FortiSOAR reduces manual SOC work by automating:
- Alert triage
- Investigation
- Enrichment
- Containment
- Notification
- Ticketing
- Incident documentation

It helps improve:
- **MTTD** (Mean Time to Detect)
- **MTTR** (Mean Time to Respond or Recover)
- Analyst productivity
- Response consistency
- Incident visibility
- Auditability

#### Q2. What is the difference between SIEM and SOAR?

**Answer:**

| SIEM | SOAR |
|------|------|
| Collects and correlates logs | Uses alerts and security data |
| Detects suspicious activity | Automates investigation and response |
| Generates alerts | Orchestrates action across tools |

**Example:**
- FortiSIEM detects a suspicious login
- FortiSOAR enriches the source IP, checks the user, blocks the IP on FortiGate if required, creates a case, and notifies the analyst

#### Q3. What is the difference between SOAR and XDR?

**Answer:**

| XDR | SOAR |
|-----|------|
| Correlates and detects threats across endpoints, email, identity, network, and cloud sources | Orchestrates actions across different tools |
| Focused on detection and investigation | Focused on workflow automation and coordinated response |

#### Q4. What is a FortiSOAR playbook?

**Answer:** A playbook is a visual or structured workflow that executes a sequence of automated and manual steps to handle a security use case.

A playbook can include:
- Triggers
- Conditions
- Loops
- Variables
- Connector actions
- Data transformation
- Decision logic
- Notifications
- Record updates
- Human approval
- Error handling

**Example:** Receive phishing alert → extract URL → check reputation → search related alerts → quarantine email → create incident → notify SOC

#### Q5. What is a connector?

**Answer:** A connector is an integration component that allows FortiSOAR to communicate with an external system through APIs, commands, or other supported methods.

**Examples of connectors for:**
- FortiGate, FortiSIEM, FortiAnalyzer, FortiEDR, FortiSandbox
- Microsoft 365, Active Directory
- Email systems
- Ticketing platforms
- Threat-intelligence platforms
- Firewalls from other vendors
- EDR and antivirus platforms

**A connector may provide actions such as:**
- Get alert
- Search indicator
- Block IP
- Disable user
- Quarantine email
- Create ticket
- Send notification
- Retrieve endpoint information

**Note:** FortiSOAR also provides a Connector Builder for creating custom integrations.

#### Q6. What is the difference between a connector and an action?

**Answer:**
- **Connector:** The integration with an external product
- **Action:** A specific operation provided by that connector

**Example:**
- **Connector:** FortiGate
- **Action:** Add IP address to an address group or create a firewall address object

#### Q7. What is alert ingestion?

**Answer:** Alert ingestion is the process of importing alerts from external security products into FortiSOAR.

**Typical sources include:**
- SIEM
- EDR
- Email security
- Threat-intelligence platforms
- Firewalls
- Cloud security tools
- Vulnerability scanners

**Note:** FortiSOAR's Data Ingestion Wizard helps configure the source, connector, mapping, and scheduling where supported.

#### Q8. What is enrichment?

**Answer:** Enrichment adds additional context to an alert or indicator so the analyst can make a better decision.

**For an IP address, enrichment may retrieve:**
- Reputation
- Geolocation
- ASN
- WHOIS information
- Related domains
- Threat-intelligence reports
- Previous sightings
- Malware associations

**Example:** A SIEM reports a connection to 203.0.113.10. FortiSOAR queries threat-intelligence services and adds reputation, country, ASN, and related incidents to the case.

#### Q9. What is the difference between an alert, incident, and indicator?

**Answer:**

| Term | Definition |
|------|------------|
| **Alert** | A detection or notification from a security system |
| **Indicator** | An observable related to potential malicious activity |
| **Incident** | A case created to investigate and manage a suspected or confirmed security event |

**Example:**
- **Alert:** "Suspicious outbound connection detected."
- **Indicator:** Malicious destination IP
- **Incident:** "Possible malware infection on workstation PC-101."

#### Q10. What is a false positive?

**Answer:** A false positive occurs when a security tool identifies legitimate activity as malicious.

**FortiSOAR response:**
1. Enrich the alert
2. Check asset and user context
3. Compare with known approved activity
4. Search previous incidents
5. Request analyst approval if needed
6. Close or suppress the alert
7. Update detection logic or allowlists where appropriate

### Playbook Development

#### Q11. What are the main components of a playbook?

**Answer:** The main components are:
- Trigger
- Input data
- Variables
- Connector actions
- Conditions
- Loops
- Data transformation
- Human approval
- Notifications
- Record updates
- Error handling
- Logging

#### Q12. What can trigger a FortiSOAR playbook?

**Answer:** A playbook may be triggered by:
- A new alert
- A new incident
- A new indicator
- A record update
- A scheduled event
- A manual button
- An API call
- An external integration
- A workflow or another playbook

#### Q13. What is the difference between automatic and manual playbooks?

**Answer:**
- **Automatic playbook:** Starts based on a defined trigger and runs without requiring the analyst to manually start it
- **Manual playbook:** Started by an analyst, such as through a button or incident action

**Examples:**
- **Automatic:** Enrich every new malicious IP alert
- **Manual:** Block an IP only after an analyst reviews the evidence

#### Q14. What is a decision or condition in a playbook?

**Answer:** A condition evaluates data and chooses the next workflow path.

**Example:**
```
If IP reputation = malicious:
    Block IP
Else:
    Assign to analyst for review
```

Conditions help prevent dangerous actions from being executed against legitimate activity.

#### Q15. What is human-in-the-loop automation?

**Answer:** Human-in-the-loop automation requires analyst approval before a sensitive action is executed.

**Example:**
1. FortiSOAR identifies a suspicious IP
2. It enriches the IP and gathers evidence
3. It asks the analyst for approval
4. After approval, it blocks the IP on FortiGate

**Useful for high-impact actions such as:**
- Disabling accounts
- Blocking business-critical IPs
- Isolating servers
- Deleting emails
- Changing firewall rules

#### Q16. What is the difference between orchestration and automation?

**Answer:**
- **Automation:** Performs a task automatically
- **Orchestration:** Coordinates multiple tools, actions, and processes into one workflow

**Example:**
- **Automation:** Block an IP on FortiGate
- **Orchestration:** Receive SIEM alert → enrich IP → query EDR → obtain approval → block IP on FortiGate → create ticket → notify management

#### Q17. What is Jinja used for in FortiSOAR?

**Answer:** Jinja is used to dynamically reference, format, transform, and construct data inside playbooks.

**Common uses include:**
- Reading values from alert or incident records
- Building API request bodies
- Creating dynamic email content
- Extracting fields
- Formatting strings
- Processing lists and dictionaries
- Passing output from one action to another

**Example:** Use the source IP from the current alert as input to a threat-intelligence connector.

#### Q18. How do you pass data from one playbook step to another?

**Answer:** The output of one action is stored in the playbook execution context. The next step references the required output using the available data mapping or Jinja expressions.

**Example:**
1. Step 1 extracts an IP address
2. Step 2 uses that IP as input to VirusTotal or another threat-intelligence connector
3. Step 3 evaluates the reputation result
4. Step 4 blocks the IP if the result meets the defined condition

#### Q19. How do you handle errors in a playbook?

**Answer:**
- Validate input data
- Check connector response codes
- Use conditions for success and failure
- Add timeout and retry logic where supported
- Log failures
- Notify the SOC analyst
- Avoid continuing with destructive actions after a failed validation
- Provide a manual fallback process

**Example:** If the FortiGate connector fails to block an IP, the playbook should create a task and notify the analyst instead of marking the incident as resolved.

#### Q20. How do you test and troubleshoot a playbook?

**Answer:**
1. Test with sample data
2. Run the playbook manually in a controlled environment
3. Review Executed Playbook Logs
4. Check each action's input and output
5. Validate connector configuration
6. Check authentication and API permissions
7. Verify Jinja expressions
8. Test success and failure paths
9. Review timeouts and API responses
10. Test again after making changes

**Note:** FortiSOAR provides playbook execution logs and supports troubleshooting of Jinja expressions and service status.

### Practical SOC Use Cases

#### Q21. Explain a phishing-response playbook

**Workflow:**
```
Email security alert received
    ↓
Create or update Alert
    ↓
Extract sender, URLs, domains, and attachments
    ↓
Enrich indicators using threat-intelligence connectors
    ↓
Check email reputation and sandbox results
    ↓
Search for other users who received the email
    ↓
If malicious:
    Quarantine or delete the email
    Block malicious URLs/domains
    Create Incident
    Notify SOC
Else:
    Assign to analyst for review
```

#### Q22. Explain a malicious-IP response playbook

**Workflow:**
```
SIEM detects connection to suspicious IP
    ↓
Create Alert
    ↓
Extract source and destination IP
    ↓
Check reputation and threat intelligence
    ↓
Search related alerts and incidents
    ↓
Check affected endpoint using EDR
    ↓
If confirmed malicious:
    Obtain approval if required
    Block IP on FortiGate
    Isolate endpoint if necessary
    Create Incident
    Notify SOC
    ↓
Record all actions and results
```

#### Q23. Explain a ransomware-response playbook

**Answer:**
1. Receive EDR or SIEM alert
2. Create or update the incident
3. Identify affected endpoints and users
4. Enrich malware hashes and indicators
5. Isolate affected endpoints through EDR
6. Disable or restrict compromised accounts
7. Block malicious domains and IPs
8. Search for lateral movement
9. Notify the incident-response team
10. Create tasks for forensic investigation
11. Coordinate recovery from clean backups
12. Document the root cause and lessons learned

**Important:** Automatic isolation or account disabling should be governed by risk, approvals, and business-impact rules.

#### Q24. Explain a brute-force login response playbook

**Answer:**
1. Receive an authentication alert from SIEM
2. Extract username, source IP, location, and target system
3. Enrich the source IP
4. Check successful and failed login history
5. Check for impossible travel or unusual behavior
6. Verify whether the source is an approved VPN or corporate IP
7. If malicious, block or rate-limit the source
8. Force password reset or revoke sessions if required
9. Enable additional monitoring
10. Create an incident and notify the analyst

#### Q25. How can FortiSOAR integrate with FortiGate?

**Answer:** FortiSOAR can use the FortiGate connector to perform supported actions through the firewall's API.

**Possible use cases include:**
- Retrieve firewall information
- Search objects
- Add or update address objects
- Add IPs to blocklists
- Update address groups
- Retrieve logs or information
- Execute approved containment actions

**Example:** A threat-intelligence playbook identifies a malicious IP and adds it to a controlled FortiGate denylist address group.

**Best practice:** Use dedicated API credentials, least privilege, approval controls, logging, and carefully scoped firewall objects.

#### Q26. How can FortiSOAR integrate with FortiSIEM?

**Answer:** FortiSIEM detects and correlates events, while FortiSOAR receives the alert and performs investigation and response.

**Typical workflow:**
```
FortiSIEM correlation rule
    ↓
FortiSOAR alert ingestion
    ↓
Indicator extraction
    ↓
Threat-intelligence enrichment
    ↓
FortiEDR or endpoint investigation
    ↓
FortiGate containment
    ↓
Incident creation and notification
```

#### Q27. How can FortiSOAR integrate with FortiEDR?

**Answer:** FortiSOAR can use FortiEDR integration to support endpoint investigation and response, depending on connector capabilities.

**Possible actions include:**
- Retrieve endpoint details
- Search endpoint events
- Investigate indicators
- Retrieve process information
- Isolate an endpoint
- Release an endpoint from isolation
- Query detection information

**Example:** When ransomware behavior is detected, FortiSOAR validates the alert and triggers endpoint isolation according to the organization's response policy.

### Incident and Case Management

#### Q28. What is the incident lifecycle in FortiSOAR?

**Answer:**
1. Alert received
2. Alert triage
3. Indicator extraction
4. Enrichment
5. Investigation
6. Incident creation or association
7. Containment
8. Eradication
9. Recovery
10. Closure
11. Lessons learned and reporting

#### Q29. What is alert deduplication?

**Answer:** Alert deduplication identifies repeated alerts that refer to the same underlying event and prevents unnecessary duplicate investigations.

**Example:** A SIEM sends 500 alerts for the same malicious IP. FortiSOAR can correlate them into one investigation or incident based on defined criteria.

**Possible correlation fields include:**
- Source IP
- Destination IP
- Hostname
- Username
- Hash
- Alert type
- Time window
- Campaign
- Detection ID

#### Q30. What is alert correlation?

**Answer:** Alert correlation links multiple related alerts to identify a broader attack pattern.

**Example:**
- Suspicious PowerShell execution
- New scheduled task
- Outbound connection to a malicious domain
- Credential access alert

Together, these may indicate one coordinated compromise rather than four unrelated alerts.

#### Q31. What is a War Room?

**Answer:** A War Room is a collaborative workspace used by SOC teams and stakeholders to investigate and respond to a serious threat or campaign.

**It can support:**
- Shared investigation
- Incident coordination
- Communication
- Task tracking
- Evidence review
- Response planning
- Stakeholder collaboration

**Note:** FortiSOAR describes War Rooms as collaborative spaces for handling critical cyber-threat scenarios or campaigns.

#### Q32. What are tasks in FortiSOAR?

**Answer:** Tasks represent individual actions required during an investigation or response.

**They may be:**
- Assigned to an analyst
- Created automatically by a playbook
- Linked to an external ticketing system
- Used to track evidence collection
- Used to track remediation

**Example:** "Verify whether the affected server contains sensitive data" is a task assigned to the incident owner.

### Administration and Security

#### Q33. What is a Solution Pack?

**Answer:** A Solution Pack is a reusable package of FortiSOAR content that may include:
- Modules
- Playbooks
- Connectors
- Dashboards
- Reports
- Widgets
- Templates
- Sample data
- Best-practice workflows

**Note:** The SOAR Framework Solution Pack provides foundational incident-response functionality.

#### Q34. What is the Content Hub?

**Answer:** Content Hub is FortiSOAR's repository for discovering and obtaining content such as:
- Solution Packs
- Connectors
- Widgets
- Agents
- Playbooks
- Other platform extensions

It helps organizations extend FortiSOAR without building every integration from the beginning.

#### Q35. How do you secure FortiSOAR?

**Answer:**
- Use role-based access control
- Apply least privilege
- Restrict administrative access
- Protect API credentials
- Use a secure password vault or Key Store
- Rotate integration credentials
- Use HTTPS and valid certificates
- Enable MFA where supported
- Keep FortiSOAR updated
- Monitor audit and playbook logs
- Back up configurations and data
- Use separate roles for analysts, administrators, and playbook developers
- Require approval for high-risk actions
- Limit connector permissions

#### Q36. What is the FortiSOAR Key Store?

**Answer:** The Key Store is used to securely manage sensitive values required by integrations and automation, such as:
- API keys
- Passwords
- Tokens
- Certificates
- Other secrets

**Important:** Secrets should not be hardcoded directly into playbooks.

#### Q37. What is role-based access control in FortiSOAR?

**Answer:** Role-based access control assigns permissions based on a user's job responsibilities.

**Typical roles may include:**
- Application Administrator
- Security Administrator
- Playbook Administrator
- SOC Analyst
- Incident Manager
- Read-only user

**Permissions should control who can:**
- View incidents
- Modify records
- Create playbooks
- Execute actions
- Manage connectors
- Change system settings
- Access sensitive data

#### Q38. What is FortiSOAR high availability?

**Answer:** FortiSOAR supports clustering for high availability and scaling. Its HA architecture uses PostgreSQL database clustering and can support:
- **Active/Passive:** Commonly used for disaster recovery
- **Active/Active:** Can support workload scaling with multiple active nodes

**The design must also consider:**
- Database availability
- Network connectivity
- Load balancing
- Backup and recovery
- Connector behavior
- Playbook execution consistency

#### Q39. What should you back up in FortiSOAR?

**Answer:**
- Application configuration
- Playbooks
- Connectors
- Credentials and secret-management configuration
- Modules and records
- Custom fields
- Dashboards
- Widgets
- Solution Packs
- Reports
- System configuration

**Note:** Backups should be protected, tested, and included in disaster-recovery exercises.

### Scenario-Based Questions

#### Q40. A playbook blocked a legitimate IP on FortiGate. How would you prevent this?

**Answer:**
- Use threat-intelligence confidence thresholds
- Require analyst approval for high-impact actions
- Use a dedicated quarantine address group
- Apply time-limited blocks
- Exclude trusted business-critical IPs
- Validate the indicator against multiple sources
- Add logging and rollback actions
- Test in a lab before production
- Use allowlists carefully
- Review automated actions regularly

#### Q41. A connector is failing. What would you check?

**Answer:**
- Connector status
- API URL and port
- DNS resolution
- Network reachability
- Firewall rules
- TLS certificate validation
- API token or credentials
- API permissions
- Rate limits
- Connector version and compatibility
- Request and response format
- FortiSOAR execution logs

#### Q42. A playbook is running successfully but produces incorrect results. What would you investigate?

**Answer:**
- Incorrect field mapping
- Wrong record type
- Invalid Jinja expression
- Incorrect data type
- Empty or missing input
- Incorrect condition logic
- Wrong connector action
- Unexpected API response
- Duplicate records
- Incorrect loop handling
- Incorrect time or date conversion

**Investigation method:** Inspect the input and output of every step using the Executed Playbook Logs.

#### Q43. How would you design a safe automatic IP-blocking workflow?

**Answer:**
```
Receive alert
    ↓
Extract IP
    ↓
Validate IP format
    ↓
Check asset criticality
    ↓
Query multiple threat-intelligence sources
    ↓
Check confidence and sightings
    ↓
Check allowlist and trusted ranges
    ↓
Apply approval policy
    ↓
Add IP to temporary FortiGate block group
    ↓
Log the action
    ↓
Notify SOC
    ↓
Expire or review the block
```

**Important:** Never blindly block every indicator received from an external feed.

**Important:** These metrics demonstrate ROI and guide continuous improvement.

## 4. Best Final Interview Statement

> "FortiSOAR is the orchestration and response layer of a SOC. It receives alerts from systems such as FortiSIEM, extracts and enriches indicators, coordinates investigation through playbooks and connectors, and can execute controlled response actions on platforms such as FortiGate and FortiEDR. I would design playbooks with validation, least privilege, logging, error handling, and human approval for high-impact actions. The goal is to reduce MTTR while maintaining accuracy, governance, and auditability."
